# Правила работы над Gmail Manager

Читать в начале каждой новой сессии. Здесь то, что не выводится из кода.

## 0. Изучение кода - ТОЛЬКО через codebase-memory MCP

Проект проиндексирован в графе (`index_repository`, проект `gmail_manager`).
Встроенный Grep/Glob/Search по коду использовать не нужно - граф уже содержит
кодовую базу и отвечает точнее.

- Найти функцию/класс/модуль: `search_graph(project="gmail_manager", query="...")`
  или `name_pattern` / `semantic_query`.
- Исходник символа: `get_code_snippet(qualified_name=...)`.
- Кто кого вызывает, откуда данные: `trace_path(function_name, mode=calls|data_flow)`.
- Текстовый поиск (строки, ключи): `search_code(pattern=..., project="gmail_manager")`.
- Общая структура: `get_architecture(aspects=[...])`.
- Изменил файлы - освежить индекс: `detect_changes` / повторный `index_repository`.
- Индекса нет -> сначала `index_repository`, потом работать.

Grep/Read допустимы для не-кода (конфиги, доки) и обязательны перед
редактированием файла - читать файл перед `Edit`.

## 1. Git: коммит + пуш после КАЖДОГО изменения

- Закончил осмысленную правку (фича, фикс, рефактор) - сразу `git commit`
  и `git push origin master`. Не копить несколько изменений в одном коммите.
- После пуша - освежить индекс графа (`index_repository` проекта
  `gmail_manager` или `detect_changes`), чтобы поиск оставался актуальным.
- Сообщение по-русски, в повелительном наклонении, по сути.
- Не коммитить сломанное: перед коммитом прогнать `node --check` по изменённым
  JS-файлам (а лучше `npm start` глазами, если менял UI/движок).
- Репозиторий: приватный `github.com/bridznostpy/gmail-manager`, ветка `master`.

## 2. Что НИКОГДА не коммитить

- `.env`, `secrets.json` - токены Telegram, API-ключи парсеров и команд.
- `userdata/`, `chrome-profiles/` - пользовательские данные Chrome, куки, логины
  Gmail. Они в `.gitignore`, не выносить оттуда.
- `node_modules/`.
- Любые реальные API-ключи и токены - даже в примерах. В коде только заглушки.

## 3. Тексты и стиль строк

- В пользовательских строках и текстах НЕ использовать длинные тире (`--`, `-`) -
  только обычный дефис `-` или переформулировать.
- Кавычки - прямые `"..."`, не `<<>>`.
- Это касается и UI-текста, и комментариев, и сообщений логгера, и README.

## 4. Контракты внешних API - только по документации

Клиенты Haron Rent / XProject / VVS реверсить нельзя - их эндпоинты и схемы
берутся из приложенной документации. Правило:

- Всё внешнее (baseUrl, endpoints, auth) живёт в блоке `CONFIG` каждого клиента
  (`src/main/link/haronRent.js`, `src/main/parser/apis/*.js`). Менять контракт -
  только там.
- Нет документации по эндпоинту - НЕ выдумывать поля. Клиент возвращает пустой
  результат и пишет warning в лог (`TODO(docs)`), а не тихо ломает прогон.
- Gmail-автоматизация (compose / чтение ответов) через CDP помечена
  `TODO(gmail-dom)` - дорабатывать против живого залогиненного DOM, не по догадкам.

## 5. Архитектура: где что

- Главный процесс общается с рендером ТОЛЬКО через IPC-хендлеры (`src/main/ipc.js`)
  и `preload.js` (`window.api`). Новый вызов из UI - новый хендлер + метод в
  preload, а не прямой `ipcRenderer` в рендере.
- Настройки - через `store.js` (JSON в userData, атомарная запись). Новое поле
  настроек добавлять в `DEFAULTS` (`store.js`), иначе не сохранится и не подтянется.
- Логи всех процессов идут через единый `logger.js` - он и питает "живые логи"
  дашборда. Новый процесс логировать через него, а не `console.log`.
- Профили и их фингерпринты - `profiles/profileStore.js` + `cdp/fingerprint.js`.
  Один профиль = один Gmail-аккаунт = один Chrome-инстанс.

## 6. Безопасность и принципы Gmail

- Авторизация в Gmail - ТОЛЬКО вручную пользователем в открытом профиле. Никаких
  Gmail API, паролей, автологина. Приложение лишь наблюдает статус через DOM-скан.
- Каждый профиль - свой `--user-data-dir` и свой фингерпринт, чтобы инстансы не
  путались и выглядели раздельно.

## 7. Проверка перед сдачей

- Менял JS - `node --check` по файлам, минимум.
- Менял UI/движок - запустить `npm start` и посмотреть глазами.
- В отчёте писать честно, что проверено, а что нет.
