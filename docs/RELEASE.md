# Как выпустить версию

Обновление доходит до людей через GitHub Releases: приложение спрашивает у
GitHub, какая версия последняя, и сравнивает со своей. Значит, релиз должен быть
опубликован, а версия в нём - выше установленной. Иначе никто ничего не увидит.

## Порядок

1. **Поднять версию** в `package.json`. Это единственное место, откуда её берут
   и приложение, и сборщик.

   Считаем так: сломали совместимость настроек - первое число, добавили
   заметное - второе, починили - третье.

2. **Закоммитить и запушить.** Собирать из непроверенного дерева нельзя: в
   релиз уйдёт то, чего нет в репозитории, и следующая правка будет вслепую.

3. **Выложить токен в окружение.** Нужен токен GitHub с правом писать релизы в
   этот репозиторий:

   ```bash
   export GH_TOKEN=<токен>
   ```

   В файл его класть не надо - `.env` и `secrets.json` не коммитятся, но токен
   не нужен и там: он живёт ровно на время сборки.

4. **Собрать и опубликовать:**

   ```bash
   npm run release
   ```

   Соберутся установщик, портативный exe и `latest.yml` - файл, по которому
   приложение узнаёт о новой версии. Все три уйдут в черновик релиза на GitHub.

5. **Опубликовать черновик** на странице релизов. Пока он в черновиках, для
   приложения его не существует.

## Проверка

Обновление нельзя проверить на одной версии - нужны две.

1. Соберите текущую версию: `npm run build`.
2. Поставьте установщик из `dist/`.
3. Поднимите версию, выпустите релиз с ней.
4. Запустите установленное приложение. Через несколько секунд появится карточка
   в углу. Нажмите "Скачать", дождитесь полосы, нажмите "Перезапустить".
5. После перезапуска версия на главной должна стать новой.

## Что мешает обновлению

Приложение пишет причину в журнал само, человеческими словами: "на GitHub нет
опубликованного релиза" или "нет связи с GitHub". Ошибку разработчика
("HttpError: 404 Not Found...") в журнал больше не выносим - она ничего не
объясняла. Неудачная проверка на старте повторяется через 20 секунд и через две
минуты: сеть на ноутбуке поднимается позже окна, и один отказ не должен
выключать проверку до следующего запуска.

- **Релиза нет совсем.** Пока на странице релизов пусто, GitHub отвечает 404 на
  запрос последней версии, и это видит каждая собранная копия при запуске.
- **Релиз в черновиках.** Самая частая причина: файлы загружены, но релиз не
  опубликован. Для GitHub черновика не существует, ответ тот же 404.
- **Версия не поднята.** Приложение сравнивает числа, а не даты сборки.
- **Нет `latest.yml` среди файлов релиза.** Без него обновление не находится:
  сам exe приложение не разглядывает.
- **Запуск из исходников.** В разработке проверка не делается вовсе - сравнивать
  не с чем. В логе будет сказано об этом прямо.

## Портативная сборка

Она обновиться сама не может: заменить свой exe на ходу нечем. Приложение
покажет ту же карточку, но со ссылкой на страницу загрузки. Это ограничение
формата, а не недоделка.
